# Graft Codebase Architecture & Intelligence Protocol

## 1. Purpose & Agent Operating Rule
Enable AI coding agents to navigate, analyze, and safely modify any repository with **zero unnecessary token consumption** by leveraging the local AST wiring graph generated by **Graft**.

> **CRITICAL AGENT INVARIANT**:
> **Never explore blindly.** Do NOT scan full source files or run broad regex searches across the codebase when trying to locate functions, classes, or interfaces.
> **Always consult Graft first:** Check `graft-query.ps1 map` or `graft/INDEX.md`, inspect the relevant `graft/<path>.md` card, and read **only** the target line range (e.g. `L60-L82`).

---

## 2. Automatic Project Bootstrapping (Any Repository)

When working on any project, verify whether Graft is initialized.

### Check Condition:
Inspect if `graft/` or `graft/.graph/wiring.json` exists in the repository root.

### If Graft is NOT initialized:
Execute the unified bootstrap script to set up Docker Buildx, query utilities, and build the initial graph:

```powershell
powershell -ExecutionPolicy Bypass -File "C:\Users\hassa\.gemini\config\skills\graft-architecture-intelligence\scripts\bootstrap-graft.ps1"
```

#### What the bootstrap script does automatically:
1. Copies `Dockerfile.graft`, `graft-build.ps1`, `graft-query.ps1`, and `AGENTS.md` from the skill templates into the project.
2. Ensures `graft/` is added to `.gitignore`.
3. Runs `graft-build.ps1` using the cached `graft-cli` Docker image.
4. Generates the initial `graft/` AST cards and outputs the zero-token `map`.

## 3. Core Commands & Workflows

### A. Repository Orientation (Zero-Token Map)
Before reading source files in an existing codebase, run:
```powershell
.\scripts\graft-query.ps1 map
```
- **Returns**: Directory clusters (subsystems), hub symbols (most called functions/classes), and coupling hotspots (most interconnected files).
- **Efficiency**: Saves ~95% tokens compared to raw directory file reads.

### B. Locating Symbols & Signatures
To find where a function, method, interface, or class is defined without opening source files:
```powershell
.\scripts\graft-query.ps1 find <symbol_name>
```
- **Returns**: Exact file path, line span (`LXX-LYY`), and type signature.

### C. Dependency & Call Graph Tracing
To check who depends on or calls a specific function or class before modifying it:
```powershell
.\scripts\graft-query.ps1 callers <symbol_name>
```
- **Usage**: Verify all callers before refactoring or changing method parameters.

### D. Interactive Graph GUI Visualization
To open the interactive visualizer in your browser:
```powershell
.\scripts\graft-query.ps1 gui
```

### E. File-Level Architectural Inspection
Instead of opening a 1,000-line source file, read the architectural card:
- Open `graft/<path_to_file>.md` (e.g. `graft/services/TabGroupService.md`).
- Inspect the listed methods and their exact line ranges.
- Use targeted read tools to open **only** the specific line range needed.

### F. Graph Rebuilding
After significant edits, adding new files, or pulling changes from Git:
```powershell
.\scripts\graft-build.ps1
```
- **Execution Time**: ~1.1 seconds (cached).
- Automatically re-parses AST and refreshes `graft/` via Docker Buildx Export.
- Automatically cleans up dangling build layers.

---

## 4. Container & Architecture Guarantees
- **Host Independence**: Operates without Node.js, Bun, or build tools installed on the host OS.
- **Remote Docker Compatibility**: Uses Docker Buildx local export (`--output type=local,dest=.`) which functions transparently across Remote Docker contexts over SSH (e.g., Debian VM).
- **Git-Ignored Cache**: The `graft/` directory acts as a local regenerable AST cache and is excluded from source control.
